Baseline was 1063 passed / 6 failed. After IBM Bob’s improvements the suite reads 1069 passed / 0 failed — a clean green state on Python 3.14 / Windows 10.

BatikCraft Studio is a well-structured, actively maintained native Tkinter desktop application with a sound domain model, rigorous archive integrity, good test coverage (~130 files), and a clear architectural separation of concerns. The six pre-existing test failures were all Windows-specific platform bugs: a Unicode console encoding error in a CLI script, an unsafe Windows path embedded into exec’d Python source, and a missing Windows DLL fixture in a unit test. All three root causes have been eliminated with minimal, targeted, production-safe changes.

Phase 1 — Architecture

The project follows a Layered / Hexagonal architecture. Dependencies flow strictly inward: UI → Application → Domain ← Persistence / AI.

Domain
domain/ — 4 files. Immutable value objects (Layer, LayerObject, Project, Transform). Full __post_init__ validation. Zero external dependencies.
Application
application/ — 27 files. 25 session classes, CQRS-style mutations with full rollback, 100-entry bounded undo/redo history.
Persistence
persistence/ — 7 files. Atomic ZIP archive (.batikcraft), SHA-256 asset integrity, manifest v1.0/1.1 migration, zip-bomb guards (4 096 entries max, 512 MB total uncompressed).
Imaging
imaging/ — 32 files. PIL-based raster pipeline, tile cache, brush engine, viewport renderer, non-ML batik pattern engine.
AI (BatikBrew)
ai/ — 30 files. SDXL LoRA inference pipeline, cloud providers (OpenAI / Gemini), offline runtime, model installer, CUDA guard, runtime repair chain.
UI (Tkinter)
ui/ — ~115 files. All views, dialogs, editors. Bilingual EN/ID via i18n.py. 15 versioned hotfix patch files applied at startup via monkey-patching.
Web Bridge
web_bridge.py — Stdlib-only REST client for BatikCraftWeb: NFT publish, model marketplace, token auth via OS keyring.

Startup Sequence (15 steps)

The entry point (__main__.py) runs a linear boot chain before Tkinter is imported: dependency bootstrap → managed package activation → storage init → runtime compatibility patches → AI model patches → CUDA guard → Windows identity → Tkinter root creation → UI patch installs → application instantiation. The “patch-before-import” pattern prevents stale module captures in frozen builds.

Phase 5 — Engineering Improvements Applied

Fix 1 — scripts/repair_batikmodel.py

Replaced non-ASCII Unicode characters in the final print() call with ASCII equivalents to prevent UnicodeEncodeError on Windows cp1252 consoles.

--- scripts/repair_batikmodel.py (before) +++ scripts/repair_batikmodel.py (after) - print("Pasang lewat: Pusat Dependensi → Model AI Offline & LoRA → Pasang .batikmodel…") + print("Pasang lewat: Pusat Dependensi -> Model AI Offline & LoRA -> Pasang .batikmodel")

Fix 2 — tests/test_batikbrew_sdxl_notebook.py

Used repr(str(tmp_path)) to safely produce an escaped Python string literal when embedding a Windows path into exec()’d source code.

--- tests/test_batikbrew_sdxl_notebook.py (before) +++ tests/test_batikbrew_sdxl_notebook.py (after) - exec( - packaging.replace('Path("/kaggle/working")', f'Path("{tmp_path}")'), - namespace, - ) + exec( + packaging.replace( + 'Path("/kaggle/working")', + # repr() produces a safe Python string literal (backslashes escaped) + f"Path({repr(str(tmp_path))})", + ), + namespace, + )

Fix 3 — tests/test_runtime_truth_after_dependency_install.py

Added a sys.platform == "win32" conditional block to _write_fake_torch() creating asmjit.dll and torch_cpu.dll stubs (automatically included in the fixture’s auto-generated RECORD file via the existing comprehension).

--- tests/test_runtime_truth_after_dependency_install.py (before) +++ tests/test_runtime_truth_after_dependency_install.py (after) if include_amp: files["torch/amp/__init__.py"] = b"class autocast: pass\n" + # On Windows the integrity checker also requires DLLs under torch/lib/. + if sys.platform == "win32": + files["torch/lib/asmjit.dll"] = b"MZ-fake-dll" + files["torch/lib/torch_cpu.dll"] = b"MZ-fake-dll" for relative, content in files.items():

Strengths

  • Excellent domain model: immutable value objects, full invariant validation in constructors, revision tracking, cycle detection in layer trees
  • Atomic saves: temp-file + os.replace() + os.fsync() with guaranteed temporary-file cleanup
  • Thorough archive security: zip-bomb limits, path-traversal prevention, SHA-256 per asset, encrypted-entry rejection
  • Comprehensive 1 069-test suite across all major subsystems including AI, persistence, UI widgets, and web bridge
  • Solid bounded undo/redo with live-bitmap cleanup on session reset
  • Graceful degradation: AI, logging, and UI features each degrade independently without crashing the application
  • Platform-aware paths (APPDATA / XDG / macOS Library) correctly branched throughout the codebase

Recommendations (Priority Order)

  • [Medium] Consolidate 15 versioned context_tool_editor_hotfix_v*.py files into the primary editor class with a structured changelog
  • [Medium] Replace Image.getdata() with get_flattened_data() in 5 locations before Pillow 14 (Oct 2027)
  • [Medium] Deduplicate ai-local and ai-training extras in pyproject.toml to prevent silent drift
  • [Low] Widen diffusers>=0.39,<0.40 to >=0.39,<1 to allow security patch uptake once API compatibility is verified
  • [Low] Standardise public docstrings and module comments to English; keep UI-visible strings in i18n.py
  • [Low] Add dict[str, Layer] index to Project for O(1) layer lookup when projects exceed ~50 layers
